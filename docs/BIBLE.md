# Bible retrieval and exact quoting

## Answer grounding: affordable default

September 9, 2026: the user chose the most affordable approach with good performance. The backend now
searches the complete public-domain BSB **before** its existing answer-generation request, then fetches
selected passages directly from Crossway for verified ESV quotations. The phone's post-answer verse cards
are additional reading; the model also receives the verified ESV evidence before writing.

`scripts/bible/build-search.py` generates `backend/src/bible/data.ts` from the bundled SQLite database.
The generated file contains the verbatim text, canonical IDs, book aliases, verse lengths, and BM25 posting
lists. It is built offline, checks the BSB public-domain metadata, and records a source SHA-256. It refuses
other translations. Run `python3 scripts/bible/build-search.py` after rebuilding the database; `./scripts/dev check`
verifies the generated index matches the current database and aliases.

`backend/src/bible/` provides these separate operations:

- Reference parsing and complete chapter/range reading over all 66 books, including common abbreviations.
- BM25 search with explicit vocabulary expansion (for example, anxiety/anxious/worry).
- A small editorial list of starting references for common topics, with remaining slots filled by ranked
  corpus matches from different chapters. These guides are inspectable in `topic-guides.ts`; they are not
  exhaustive, denominational policy, or a substitute for wider reading.
- Context assembly: requested verses first, surrounding verses, up to six passages and 12,000 serialized
  UTF-16 characters. Ordinary chapters fit; long selections stop at verse boundaries and are marked partial.
  Short follow-ups can use the preceding exchange for retrieval. The full conversation is still sent intact.

The model receives an explicitly editorial overview of the Bible's literary groups and the selected evidence.
It is instructed to ignore irrelevant matches, distinguish text from interpretation, and avoid claiming
exhaustive coverage. This is **automatic retrieval before one generation**, not an autonomous multi-round
Bible tool loop or a semantic embedding service. Questions needing broader evidence or external commentary
can still use the existing approved web search. The prompt directs the model not to pay for web search when
the supplied text is sufficient; this is a model instruction, not a guarantee of zero web calls.

`AnswerSources.addBible` seeds the same citation checker used for web evidence. The current answer-style
prompt prefers **ESV direct quotations**. `prepareBible` fetches up to three selections (at most 16 verses
each) in one Crossway request, prioritizes the returned ESV evidence, and fills remaining context with BSB.
Both translations together retain the six-passage / 12,000-character limit. Returned references must fall
within the requested ranges. The answer prompt prefers supplied ESV over paying for web search for the same
text. BSB supports wider context and cited paraphrases; it is never relabeled ESV. The checker can also
validate BSB quotations: they must match the supplied text and end their attribution with BSB. It never
accepts that text relabeled as ESV. Canonical Bible.com reading links are generated from
verse IDs; their pages are not fetched as evidence. Source titles identify the bundled Bible. Web annotations
cannot overwrite the corpus evidence. Existing clients accept these `sources`/`quotes` without an app update.

BSB discovery adds no paid embedding/search API, database binding, migration, or secret. The corpus is parsed once
per Worker isolate and searched using posting lists. The optional Crossway layer uses only the server
`ESV_API_KEY`; users never supply it and it is never sent to OpenRouter. The selected context still costs normal model input
tokens, and its actual UTF-8 size is included in the existing usage reservation. Provider usage remains the
settlement source. No ESV text is indexed or cached on the backend. Crossway responses have a 256 KiB
body cap, a six-second grounding deadline, and no automatic retry or redirect following. Outages or quota
exhaustion preserve BSB context; the model can paraphrase or obtain verified ESV via approved web search.

## What is bundled and why

The app ships the complete **Berean Standard Bible (BSB)** in `Untitled Faith/Resources/Bible.sqlite` (about 7 MB,
31,086 verses). The BSB was dedicated to the public domain in 2023, so it can be stored, searched, and quoted offline
without a license. The database is generated by `scripts/bible/build.py`, which accepts any tab-separated verse file
("John 3:16<TAB>text…") and records the translation's name, license, and notice in the file.

The **ESV** is copyrighted by Crossway. Crossway's API terms (api.esv.org) allow up to 500 verses per query,
5,000 queries per day, and at most 500 verses stored locally; they do not allow downloading the whole Bible. The API is
free for non-commercial use, and commercial use needs Crossway's permission. So the app never bundles ESV text.
Instead the backend fetches exact ESV passages on demand and the app caches at most 500 verses on the device.

If Crossway grants a text license later, export the licensed text to the tab-separated format and rebuild the
database with `--id ESV` for the device's translation-agnostic search and quoting path. The backend BSB index
deliberately rejects ESV; licensed indexing and AI use would need a separate implementation under that license.

## Exact quoting

1. `ScriptureReferenceDetector` finds references in an answer ("Rom. 8:28–30", "1 Pet 5:7", "Psalm 23").
2. `ScriptureQuoter` resolves each reference:
   - from the device `PassageCache` (capped at 500 verses, entries expire after 30 days), else
   - from `GET /v1/passages?q=John+3:16;Romans+8:28` on the backend, which calls Crossway with the server-side
     `ESV_API_KEY` (footnotes and headings off, verse numbers rendered as superscripts), else
   - from the bundled BSB through `BibleStore`.
3. Cards show the reference and translation ("John 3:16 · ESV" or "· BSB") with the verbatim text.

`BibleReference` parses and formats references, and `BibleBook` holds the 66 books with common abbreviations.

## Search

- **Keyword and phrase search** use the SQLite FTS5 index in the bundled database: `BibleStore.search(words:)`
  requires every word; `search(phrase:)` matches the exact phrase. Both rank by BM25 and run offline.
- **Semantic search** uses `VerseEmbeddingIndex`, built on the device from Apple's sentence embeddings
  (`NLEmbedding`), 512 dimensions per verse stored as half floats (about 32 MB for the whole Bible). The index file
  is keyed by the embedding revision so OS model updates rebuild it. Cosine search over all verses takes a few
  milliseconds with Accelerate. Nothing leaves the device.
- References are translation-independent, so semantic or keyword search over the BSB can drive ESV quoting.

Nothing schedules a full-Bible **device embedding** build yet; `VerseEmbeddingIndex` is exercised by tests on
a subset. Answer grounding uses the backend BM25 index described above. Semantic embeddings remain a possible
later improvement if evaluation shows the lexical search misses too many relevant passages.

## Enabling ESV passages

1. Get an API key at https://api.esv.org and confirm the usage tier matches the app's commercial status.
2. Locally: add `ESV_API_KEY` to `backend/.dev.vars`. Deployed: `npx wrangler secret put ESV_API_KEY`.
3. Deploy the Worker; the rate limiter `PASSAGES_RATE_LIMITER` (20 requests per user per minute) is in `wrangler.jsonc`.
4. Without the key the endpoint returns `503 not_configured` and cards fall back to the BSB automatically.

Settings shows the Crossway copyright notice and the BSB attribution.

The user supplied the Crossway key on September 9, 2026. It is stored in the ignored `backend/.dev.vars`
with mode 0600 and in the deployed Worker as `ESV_API_KEY`. Only the token value is stored; the Worker adds
the `Authorization: Token` prefix when calling Crossway. Both the passage endpoint and answer grounding
require app authentication before any Crossway call, and share the existing per-user passage limiter.
The limiter is per Cloudflare location, not a global enforcement of Crossway's application-wide quota.
BSB grounding works without the key. Before expanding ESV use, establish the applicable Crossway permissions for the funding model, AI prompt
context, embeddings, and retained chat quotations. The standard API's storage limits include half a book,
not just a total 500-verse cap. See [Crossway API terms](https://api.esv.org/) and
[permissions](https://www.crossway.org/permissions/).

## Rebuilding the database

```
scripts/bible/build.py --source https://bereanbible.com/bsb.txt --id BSB \
  --name "Berean Standard Bible" --license "Public domain" \
  --notice "The Holy Bible, Berean Standard Bible, BSB is produced in cooperation with Bible Hub, Discovery Bible, unfoldingWord, Bible Aquifer, OpenBible.com, and the Berean Bible Translation Committee. This text of God's Word has been dedicated to the public domain."
```
